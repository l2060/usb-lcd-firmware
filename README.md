# MSU2 LITE 自定义固件（非官方）

> **本项目是第三方社区作品，与 MSU2 LITE 的原厂 / 品牌方没有任何关系。**
> 我们只是针对该硬件**重新实现了固件与上位机工具**，不销售、不代理、不代表该产品。
> "MSU2 LITE" 等名称与商标归其各自所有者。刷写自定义固件可能导致设备无法使用、失去保修，
> 请自行评估风险。

把 MSU2 LITE 这块 USB 小屏变成更好用的"桌面状态屏 / 副屏"：
插上 USB 就是一个串口设备，上位机可以实时推画面、推文字、画图形，也可以把整个桌面投影上来。

固件（APP + Bootloader）与上位机均为本仓库自行实现，支持 USB 串口升级，不需要拆机或短接。

```
┌─────────────┐   USB CDC    ┌──────────────────┐
│  上位机      │ ───────────► │  CH32X033F8P6    │ ── SPI ──► GC9307 320×172
│ Aurora Suite │ ◄─────────── │  62KB Flash      │            IPS 面板
└─────────────┘   自定义协议  │  20KB SRAM       │ ── SPI ──► W25Q64 8MB
                              └──────────────────┘      （背景图 / 字库）
```

## 一、这个项目能做什么

| 能力 | 说明 |
|---|---|
| 实时推屏 | 脏矩形差分 + 无 ACK 流式协议，19–21 fps，单帧 20–60ms |
| 桌面投影 | 勾选「投影屏幕」，把 Windows 桌面等比缩放到 320×172 实时显示 |
| 侧边监控 | 附带 Linux 主机程序（`host/AuroraHost`），读取 `/proc` 显示 CPU/内存/网络 |
| 开机图 | 任意图片压缩后存外部 Flash，开机自动显示，掉电保持 |
| 设备端字库 | 任意系统字体/字号/粗细烘焙成 8-bit alpha 图集，MCU 直接渲染抗锯齿文字 |
| 矢量图元 | 矩形（圆角/边框）、圆/椭圆、直线，填充与边框可用不同颜色 |
| USB 升级 | 上位机选 hex 文件即可升级 APP，自动进 Bootloader、校验、跳转 |
| 屏幕方向 | 0°/90°/180°/270°，存放在内部 Flash，断电不丢 |

## 二、硬件前提

本固件**只适用于**搭载下列器件的 MSU2 LITE 硬件（同方案的自制板也可）：

| 器件 | 型号 | 关键参数 |
|---|---|---|
| MCU | CH32X033F8P6 | RISC-V RV32IMAC @48MHz，62KB Flash，20KB SRAM，内置 USBFS |
| 显示驱动 | GC9307 | 172×320 IPS，4-wire SPI，RGB565 |
| 外部 Flash | W25Q64 | 8MB SPI NOR，4KB 扇区 |
| 可见区域 | 1.47" | 横屏使用 320×172 |

**引脚（本固件实际使用）**

| 功能 | 引脚 |
|---|---|
| LCD SCK / MOSI | PA5 / PA7 |
| LCD DC（与 Flash MISO 复用） | PA6 |
| LCD RST / CS | PA0 / PC3 |
| Flash CS | PB7 |

> ⚠️ PA6 同时是 LCD 的 DC 和 Flash 的 MISO。**LCD 窗口打开期间（CS 低）绝对不能读外部 Flash**，
> 否则会中断窗口写入，导致像素丢失、错位甚至花屏。详见 [docs/PROTOCOL.md](docs/PROTOCOL.md)。

更多硬件细节（分区表、外部 Flash 布局、资料缺口）见 [docs/HARDWARE.md](docs/HARDWARE.md)。

## 四、快速开始

### 1. 准备

- 硬件：MSU2 LITE（或同方案的 CH32X033 + GC9307 板）
- 第一次烧录：WCH-Link / DAP-Link（SWD），或厂商烧录工具
- 上位机：Windows 10/11 x64 + [.NET Desktop Runtime 11](https://dotnet.microsoft.com/download)
- **务必备份**：先用厂商工具把原厂固件与外部 Flash 完整读出（见 `docs/images/`），以便回退

### 2. 烧录本项目的 Bootloader（只需一次）

用 SWD 工具把 `BL_v67.hex` 写入芯片，起始地址 `0x00000000`。

上电后屏幕先显示开机图，右下角有 5→1 倒计时：

- **不操作**：倒计时结束后跳转到 APP（正常使用）；
- **倒计时内**：保持停留在 Bootloader，等待上位机升级。

### 3. 烧录 APP

两种方式任选：

**A. 用上位机（推荐，之后都走这个）**

1. 打开 `Aurora Suite`，选择串口（如 `COM5`）→ 点「连接」
2. 若设备在 Bootloader 模式，进「固件升级」页 → 选择 `APP_v104.hex` → 点「上传并运行」
3. 工具会自动等待设备重启并重新连接

**B. 用 SWD** 直接把 `APP_v104.hex` 写到 `0x9200`。

> 想回到原厂固件：把 `docs/images/` 里的原厂备份写回对应地址即可。

### 4. 使用上位机

启动 `AuroraSuite.exe`，界面左侧是功能页：

| 页面 | 用途 |
|---|---|
| **设备概览** | 型号/固件/端口/容量、屏幕方向（0/90/180/270，断电保持） |
| **固件升级** | USB 升级 APP；可切到 Bootloader；显示 Flash 校验结果 |
| **开机背景** | 上传开机图（压缩后存外部 Flash，开机自动显示） |
| **APP 背景** | 上传当前运行的背景图，掉电保持 |
| **画面调试** | 单次推送整帧 / RLE / 区域块，内置测试图案与图形图元测试 |
| **流式推送** | 实时推流；勾选「投影屏幕」把桌面投到设备 |
| **字库烘焙** | 选系统字体/字号/粗细 → 烘焙 alpha 图集 → 上传到设备（最多 768KB） |
| **字库调试** | 拖动文字实时上屏，验证字库效果与位置 |
| **运行日志** | 分级日志：每帧字节数、耗时、GC 分配 |

推荐流程：

```
① 设备概览 → 读取，确认连接与屏幕方向
② 开机背景 / APP 背景 → 上传一张图，确认显示正常（静态底图）
③ 字库烘焙 → 烘焙一次常用字体（如微软雅黑 20px）→ 上传
④ 字库调试 → 拖几个数值文字，验证位置和颜色
⑤ 流式推送 → 长时间运行，观察帧率与字节数
```

### 5. 桌面投影

1. 「流式推送」→ 勾选 **投影屏幕**
2. 点「开始推送」
3. 设备上出现桌面实时画面（等比缩放、上下留黑边，不改比例）

> 投影时按脏矩形差分发送：画面静止时几乎不发数据，适合长期挂着。

### 6. Linux 主机监控（可选）

`host/AuroraHost` 是一个 .NET 控制台程序，读取本机 `/proc` 的 CPU/内存/网络/磁盘，
生成仪表盘画面并推送到 `/dev/ttyACM0`：

```bash
cd host/AuroraHost
dotnet run -- /dev/ttyACM0
```

## 五、自定义协议速查

完整协议见 [docs/PROTOCOL.md](docs/PROTOCOL.md)。**这是本项目的私有协议，与原厂协议无关。**

```
帧格式: A5 5A | ver | flags | seq | cmd(2 LE) | len(2 LE) | payload | crc16
最大载荷 2048 字节，除流式包外每条命令均需 ACK
```

| 命令 | 值 | 用途 |
|---|---|---|
| `INFO` | 0x0001 | 设备信息（模式/容量/页大小） |
| `DISP_RLE` | 0x0105 | 整屏 RLE |
| `DISP_BLIT` | 0x0106 | 指定矩形 RLE |
| `STREAM_*` | 0x0120–0x0123 | 流式会话（无 ACK，单次 CRC 提交） |
| `DISP_TEXT` | 0x0132 | 设备端字库渲染 `face x y w h fg bg text` |
| `DISPLAY_SET/GET` | 0x0140/0x0141 | 屏幕方向 |
| `DRAW_RECT` | 0x0150 | 矩形（圆角、填充/边框独立配色） |
| `DRAW_ELLIPSE` | 0x0151 | 椭圆/圆 |
| `DRAW_LINE` | 0x0152 | 直线（可设粗细） |

## 六、从源码编译

### 固件

需要 `riscv64-unknown-elf-gcc` 14.2+ 与 picolibc：

```bash
cd src
./build.sh app     # → app/app.hex
./build.sh bl      # → bl/bl.hex
```

### 上位机

```bash
cd host/AuroraSuite
dotnet build            # 开发构建
dotnet publish src/Aurora.App -c Release -r win-x64 --self-contained false -o ../../dist
```

## 七、常见问题

**Q：连接后显示 "Bootloader 模式"，按钮都是灰的？**
设备停在 Bootloader，点「运行应用」或断电重启让倒计时走完。

**Q：刷完固件后工具连不上？**
设备会重启重新枚举，工具会自动重连（约 1 秒）；若端口号变了，工具会把新端口找出来并提示。
仍失败时点「刷新」再手动连接。

**Q：屏幕方向改了没反应？**
方向写入后需要**断电重启**才生效（BL 和 APP 都在启动时读取）。

**Q：文字边缘有一圈黑边？**
设备端字库的 alpha 混合需要一个「背景色」。纯色卡片请把背景色设为卡片底色；
渐变/图片背景请改用主机渲染 + `DISP_BLIT`。

**Q：推流时提示 CRC 校验失败？**
画面变化太剧烈导致单帧数据过大，工具已按 2KB 分批提交；仍失败可降低刷新频率。

**Q：能刷回原厂吗？**
可以。`docs/images/` 保留了原厂内部 Flash 与外部 Flash 的备份，用厂商工具写回即可。

## 八、状态与版本

| 组件 | 版本 | 说明 |
|---|---|---|
| 自定义 APP | v104 | 字库、图元、方向、流式 |
| 自定义 BL | v67 | USB 升级、开机图、倒计时 |
| Aurora Suite | 持续更新 | Windows WPF 调试工具 |

已知限制：

- BL 区仅剩约 500 字节空间，新增功能可能需要精简或重新分区；
- 设备端图元无抗锯齿（圆角/圆会有 1–2px 阶梯），追求效果建议主机预渲染后整块下发；
- 面板为 RGB565（65,536 色），渐变可能出现色带，可用抖动缓解。
